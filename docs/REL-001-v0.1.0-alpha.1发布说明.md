# REL-001：v0.1.0-alpha.1 发布说明

## 发布定位

`v0.1.0-alpha.1` 是 Hatch 的首个公开源码预发布，用于让开发者、Agent 产品经理和 UI 设计师验证本地优先架构、公开 Button Demo 与治理边界。

这不是生产稳定版，不是 npm 包发布，也不表示真实 Figma Desktop 视觉验收已经完成。发布物是 GitHub 上与 Tag 对应的源码快照，使用者需在本地构建。

## 可以验证的主链路

```text
公开 Brief／Token／Button Contract／Registry
→ 严格校验
→ Agent 精确搜索与 Variant 解析
→ 确定性 Instance 编排（自动 Harness）
→ 样式／组件来源／Registry 漂移审计
→ 断线、冲突与精确重放失败矩阵
```

公开 Quickstart 全程只读，不需要云服务器、数据库、账号或 Figma 文件。Figma Development Plugin 与诊断 Bridge 连接是可选步骤。

## 核心交付

- Git Catalog：Brief、DTCG Token 子集、Button Contract、Registry 与 Approval 严格 Schema；
- Agent 入口：只读 CLI、stdio MCP Status／Brief／Token／Component 查询、精确 Resolve 与 Change Request；
- 本地 Writer 基础：认证 Loopback Bridge、唯一 Plugin Writer、FIFO、租约、幂等、脱敏 Operation Log；
- Figma 底层能力：Variables Ensure、Button Component Set Ensure、Registry 原子 Ready、Button Instance Insert；
- Agent 可选 Writer Tool：已 Ready Button 的 Instance 插入；
- 审计：硬编码样式／未登记 Variable、Instance／Variant／来源和 Registry／Figma 双向差异；
- 发布证据：Agent 黄金路径、系统失败矩阵、Node 24／22 统一门禁、历史 M0 回归和文档契约。

完整变更见 [CHANGELOG](../CHANGELOG.md)，安装见 [五分钟 Quickstart](DOC-001-安装与五分钟Quickstart.md)，运行时边界见 [当前架构](DOC-002-当前架构与运行边界.md)。

## 安全失败边界

- Agent 默认只读；只有 MCP Host 同时获得当前 Bridge URL 和 Session Token 时才出现 Writer／Figma Audit Tools；
- Bridge 只监听 `127.0.0.1`，Token 只驻留本地进程内存；
- 每次写入前重读 Git Approval，并核验准确版本、摘要、Registry 和 File Binding；
- 不自动删除、Detach、Swap、降级、Adopt 或 Rebind；
- 部分写入保留可恢复 Marker，不伪装成功。

安全问题请通过 [GitHub Private Vulnerability Reporting](https://github.com/KinoKo668/hatchkit/security/advisories/new) 私密提交，不要在公开 Issue 中粘贴 Token、Header、客户文件或未脱敏日志。

## 已知限制

- 公开 `hatch-demo` 故意不提供可信人工 Approval Record，所以正式 Figma 写入会失败关闭；
- FIG-003 至 FIG-006 仍需真实审批与独立 Figma Desktop 文件中的双次运行、重开定位和设计师视觉验收；
- Variables 和 Component Set 建库底层链路已实现，但尚未暴露为面向 Agent 的公开 MCP Tool；
- 当前 Instance 插入仅限同一已绑定 Figma 文件，尚未完成跨文件 Library Publish／Import；
- Icon、Input、三套 UI Direction、无障碍审计和多 Agent Writer 尚未完成；
- 尚无图形化安装器、云服务或完整组件库。

## 安装与验证

```bash
git clone --branch v0.1.0-alpha.1 --depth 1 https://github.com/KinoKo668/hatchkit.git
cd hatchkit
nvm use
corepack enable pnpm
pnpm install --frozen-lockfile
pnpm --silent hatchkit --version
pnpm release:check
```

预期 CLI 版本为 `0.1.0-alpha.1`。`release:check` 必须通过 Node 24.20.0 的格式、Lint、类型、全部测试、构建、MCP／Bridge／Plugin 冒烟、高风险依赖审计和 M0 历史回归。GitHub Tag 还会触发 Node 24.20.0 与 22.22.2 双版本 Quality Workflow。
