# ADR-003：平台官方组件库优先与外部资产边界

- 状态：已接受
- 决策日期：2026-09-02
- 任务：PLAT-001
- 依赖：ADR-001、ADR-002、SCH-004、FIG-007

## 1. 决策背景

Hatch 面向 iOS、iPadOS 与 Android 设计页面时，不应把平台原生控件重新绘制成近似组件。Apple 和 Google 已提供官方 Figma UI Kit；平台组件在结构、状态、命名、系统行为与实现框架上比通用自建组件更接近真实产品。

官方资产同时存在三个边界：

1. 它们由平台厂商拥有，不是 Hatch 可以重新打包发布的开源素材；
2. Figma Plugin 只能导入调用方有权访问的已发布组件，不能替用户启用 Library 或接受许可；
3. iOS 与 Android 的同一产品语义可能对应不同组件，不应共用一个视觉实例。

## 2. 冻结结论

APP 页面中的组件解析顺序固定为：

```text
平台系统组件
→ 当前目标版本的官方 Vendor Library
→ 包裹官方 Instance 的品牌组合组件
→ Hatchkit 管理的项目组件
→ Change Request
```

禁止：

- 用 Token 重画官方库中已经存在的原生组件；
- 把 Apple 组件用于 Android，或把 Material 组件冒充 iOS 原生组件；
- Detach 官方 Instance 后把副本登记为官方来源；
- 找不到准确组件时自动选一个名称相近的组件；
- 把 Apple／Google Figma 资产文件、节点或矢量内容提交到 Hatch 仓库；
- 在没有准确版本、Library 和 Component Key 的情况下声称插入了官方组件。

## 3. 版本策略

每个项目必须显式选择 Platform Target：

- `platform`：`ios`、`ipados` 或 `android`；
- `osVersion`：项目采用的系统版本；
- `releaseChannel`：`stable` 或 `preview`；
- `implementationFramework`：SwiftUI、UIKit、Compose 或 Android Views；
- `nativeFidelity`：严格原生、适配或品牌化。

Apple 项目不能同时把 iOS 26 与 iOS 27 当作同一条默认轨道。当前正式产品可使用 iOS 26 Stable；面向下一代系统的项目可以显式选择 iOS 27 Preview。Preview 不得进入 Stable Target。

Android 不以一个年度系统版本代替 Material 设计体系版本。Target 同时记录 Android OS 基线与具体 Android UI／Material Kit 版本。

版本更新不静默接受：作者发布 UI Kit 更新后，Hatch 先产生差异与审计结果，再由人批准新的 Platform Binding。

## 4. 跨平台语义

Component Contract 继续表达产品语义，例如 `button` 和 `appearance-primary/state-default`。Platform Component Registry 负责把同一语义映射到各平台的真实发布组件：

```text
button / primary / default
├── iOS 26 → Apple published Component Key
├── iOS 27 Preview → Apple published Component Key
└── Android Material 3 → Google published Component Key
```

映射必须完整覆盖 Contract 的 Variant；不允许用一个 Component Key 填补多个未经验证的 Variant。

## 5. Git、Figma 与许可边界

Git 只保存：

- 官方来源 URL、Publisher、Kit 名称与版本；
- Release Channel 与支持平台；
- Figma Library Key、发布 Component Key 和语义映射；
- 验证时间、审批引用与授权策略标记。

Figma 保存并授权实际外部 Library 与 Instance。Hatch 不保存、复制或重新发布官方模板内容。

Apple Design Resources 只能按 Apple 的许可用于 Apple 平台界面 Mockup；Hatch 将其统一标记为 `external-reference-only`，并要求用户在 Figma 中自行启用和接受许可。Google／Material 资源同样默认作为外部授权依赖，除非具体资源另有明确可再分发许可。

## 6. 运行时门禁

官方 Instance 插入必须同时满足：

1. Platform Target 与当前请求一致；
2. Registry Entry 为唯一 Active；
3. 官方 Library 已完成 Figma 验证；
4. Platform Binding Review 已批准；
5. 准确 Variant 存在唯一 Component Key；
6. 当前用户有权导入发布组件；
7. Plugin 回读结果确认 `remote = true` 且来源 Key 一致；
8. Instance 未 Detach，写后审计通过。

任一条件不满足时零写入，并返回可恢复错误或 Change Request。

## 7. 成本与部署

平台官方组件能力继续走本地 MCP Server 与 Hatchkit Writer，不增加云服务器、数据库或账号系统。Figma 官方 MCP 的 Library 搜索可以作为可选加速路径，但不能成为唯一依赖，因为其可用性、计划权限和未来计费不由 Hatch 控制。
