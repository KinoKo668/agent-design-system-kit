# CLI-001：本地只读命令

## 1. 目标

CLI-001 为设计师、开发者和自动化脚本提供第一条可直接运行的本地查询链路：

```text
显式选择 Git 中的设计系统文件
→ 安全读取
→ 校验 Schema、跨文件引用与内容摘要
→ 搜索或精确解析 Component
→ 找不到能力时生成 Change Request
```

CLI 不连接网络、不读取凭据、不修改设计系统文件，也不向 Figma 发送写入命令。

## 2. 为什么使用显式文件清单

CLI 只依赖 `@agent-design-system-kit/core`，不能依赖或启动 `mcp-server`。为了不复制 MCP Server 的递归目录发现器，CLI 要求调用者显式提供 Brief、Token Set、Component 与 Registry 的相对路径。

这种方式适合 MVP 的人工验证和 CI：输入明确、顺序可确定、不会意外读取同一目录中的错误样例或未纳管 JSON。后续 MCP Server 仍使用 REG-001 的受管理目录发现器。

## 3. 构建与帮助

```bash
pnpm build
pnpm --silent hatchkit --help
```

`package.json` 同时登记了 `hatchkit` Bin。当前仓库内通过根脚本调用构建后的 Bin；未来发布 Package 时可以直接使用同名命令。

## 4. 公共示例 Catalog

以下参数选择仓库中四份彼此一致的公开样例：

```text
--project hatch-demo
--root design-system/hatch-demo
--brief briefs/hatch-demo.brief.json
--token-set tokens/button-foundation.tokens.json
--component components/button.component.json
--registry registry/components.registry.json
```

`--root` 可以是绝对或相对工作目录的路径；所有来源必须是该 Root 内的规范化 POSIX 相对路径。每类来源参数均可重复。

## 5. Validate

```bash
pnpm --silent hatchkit validate \
  --project hatch-demo \
  --root design-system/hatch-demo \
  --brief briefs/hatch-demo.brief.json \
  --token-set tokens/button-foundation.tokens.json \
  --component components/button.component.json \
  --registry registry/components.registry.json
```

成功结果只返回项目、各类资产数量、相对来源路径和 `status: valid`，不会把完整设计数据重复打印一遍。

校验覆盖：

- 严格 Schema 与项目身份；
- Brief、Token、Contract、Registry 跨文件引用；
- Component Contract 与 Registry 的准确内容摘要；
- 文件名、文件类型、大小和 JSON 语法；
- 根目录逃逸、重复来源与软链接。

## 6. Search

```bash
pnpm --silent hatchkit search \
  --project hatch-demo \
  --root design-system/hatch-demo \
  --brief briefs/hatch-demo.brief.json \
  --token-set tokens/button-foundation.tokens.json \
  --component components/button.component.json \
  --registry registry/components.registry.json \
  --term Button
```

支持 `--asset-id`、`--asset-version`、`--term`、`--lifecycle` 与 `--figma-status`。搜索规则来自 REG-002：只做忽略大小写的完整匹配，不做模糊猜测；默认只返回 Active。

## 7. Resolve

```bash
pnpm --silent hatchkit resolve \
  --project hatch-demo \
  --root design-system/hatch-demo \
  --brief briefs/hatch-demo.brief.json \
  --token-set tokens/button-foundation.tokens.json \
  --component components/button.component.json \
  --registry registry/components.registry.json \
  --asset-id button \
  --variant appearance=secondary \
  --variant state=disabled
```

Resolve 只接受准确 Asset ID、可选 SemVer 和 Contract 已登记的 Variant。成功结果明确区分 `figma-ready` 与 `ensure-required`，并保留审批与审计 Warning；命令本身不会执行这些后续动作。

## 8. Request Change

当准确 Variant 不存在时，使用调用方提供的 UUID 和时间生成可复现的申请：

```bash
pnpm --silent hatchkit request-change \
  --project hatch-demo \
  --root design-system/hatch-demo \
  --brief briefs/hatch-demo.brief.json \
  --token-set tokens/button-foundation.tokens.json \
  --component components/button.component.json \
  --registry registry/components.registry.json \
  --asset-id button \
  --variant appearance=tertiary \
  --request-id 00000000-0000-4000-8000-000000000020 \
  --submitted-at 2026-09-01T16:30:00Z \
  --submitted-by codex \
  --summary "Add a tertiary Button appearance" \
  --rationale "The approved Button does not contain the required low-emphasis appearance." \
  --intended-use "Use it for the low-emphasis action in a settings footer."
```

结果是 `change-request-required`，不是 Figma 写入指令。申请不会包含 Figma Locator、Main Component Key 或 Node ID，并显式禁止近似绘制、回退旧版本、发明 Variant 与排队写入。

## 9. 输出与退出码

除帮助文本外，所有命令只向标准输出写一个 Toolkit Result JSON：

| 退出码 | 含义 |
| --- | --- |
| `0` | 命令成功，包括成功产生需要人工分诊的 Change Request |
| `1` | 文件、设计系统或查询校验失败 |
| `2` | CLI 参数使用错误 |
| `70` | 未预期的 CLI 内部错误 |

输出只包含设计系统 Root 内的相对来源路径，不泄露本机绝对路径或底层操作系统错误。

## 10. 当前边界

CLI-001 不实现：

- 自动递归发现文件；
- 写回或自动修复 JSON；
- MCP 协议与 Agent Tool；
- 审批记录查询；
- Figma 连接、资产创建或 Instance 插入。

下一阶段由 MCP-001 启动本地 MCP Server，再逐步把同一套 Core 查询服务暴露给 Codex 等 Agent。
