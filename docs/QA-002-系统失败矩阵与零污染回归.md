# QA-002：系统失败矩阵与零污染回归

## 1. 目标

QA-002 在 QA-001 成功基线之上验证关键失败不会被误报为成功，也不会产生重复或越权的 Figma 派发。

可单独执行：

```bash
pnpm qa:failures
```

## 2. 正式失败矩阵

测试使用真实的进程内 MCP Client／Server、HTTP Local Writer Client、认证 Figma Bridge、Writer Queue 和持久化 Operation Log，覆盖：

| 场景                                     | 期望结果                            | 零污染证据                                          |
| ---------------------------------------- | ----------------------------------- | --------------------------------------------------- |
| 请求不存在的 Component                   | `IDENTITY_NOT_FOUND`                | Bridge Operation 数为 0                             |
| Ready Component 合法，但 Plugin 未连接   | `OPERATION_TIMEOUT`，允许同请求恢复 | Operation 保持 `queued`、`attempt: 0`、无 In-flight |
| 断线后精确重试同一请求                   | 再次返回可恢复超时                  | Queue 中仍只有一个 Operation                        |
| 相同 Request／Idempotency Key 改变 Label | `IDEMPOTENCY_CONFLICT`              | 原 Operation 未改变、未派发                         |
| 成功请求精确重放                         | 返回原成功结果                      | Operation 总数为 1、`attempt: 1`、Queue 为空        |
| 成功后复用 Request ID 改变意图           | `IDEMPOTENCY_CONFLICT`              | 不产生第二次 Plugin 派发                            |

这里的 `attempt` 是 Bridge 真正向 Plugin 租出命令的次数。`attempt: 0` 比单纯检查错误文案更强：它证明失败发生在 Figma Writer 获得命令之前。

## 3. 成功重放验证

第二组测试连接一个受控 Plugin 会话，并只接收一次真实 Writer Delivery。测试根据 Delivery 中的确定性 Instance Plan 回报合法 Result，然后：

1. 首次 Agent Tool 调用成功；
2. 完全相同的 Tool 调用从终态 Operation 返回相同结果；
3. Queue 中仍只有一条 Operation；
4. `attempt` 保持 1；
5. 之后改变 Label 的同 ID 请求在 Bridge 被拒绝。

这证明“重复调用 Tool”不等于“重复写入 Figma”。

## 4. 边界

- 测试中的 Bridge 写授权使用受控测试许可，只用于到达 Queue 与重放边界；真实运行仍必须由 Git Approval Verifier 授权。
- 成功场景由测试 Plugin 回报严格符合协议的 Result，不调用 Figma Mutation API，也不替代 Desktop 验收。
- Partial Write 的恢复、真实属性再审计和禁止自动 Delete／Detach／Swap 已由 FIG-003 至 FIG-007 的专项测试覆盖；QA-002 不复制这些底层实现测试。
- 测试只使用临时 Operation Log 目录，完成后清理，不写用户设计系统或 Figma 文件。

## 5. 发布门禁

失败矩阵属于正式 Vitest 测试集，因此会随 `pnpm test`、`pnpm check` 和 GitHub Node.js 24／22 Quality Workflow 自动执行。`pnpm qa:failures` 提供更快的本地单项诊断入口。
